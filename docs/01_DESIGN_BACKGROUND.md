# 1. DESIGN_BACKGROUND.md —— 设计背景

## 1.1 项目背景

随着 Ethereum 生态中去中心化交易所（DEX）的发展，自动做市商（AMM）机制成为链上资产交易的重要基础设施。

以 Uniswap V2 为代表的 AMM 通过流动性池储备量决定交易价格。当用户提交 Swap 交易时，交易执行前后的池子状态可能发生变化。在公开交易排序环境下，攻击者可以利用交易排序机制，将自己的交易安排在目标用户交易之前和之后，从而形成三明治攻击（Sandwich Attack）。

典型三明治攻击由三笔交易组成：

1. Front-run：攻击者先于受害者交易执行，改变流动性池状态。
2. Victim：受害者执行交易，承受不利的成交价格。
3. Back-run：攻击者在受害者交易之后反向交易，获取资产价差。

## 1.2 问题定义

本项目关注的问题是：

如何通过已打包区块中的交易顺序、DEX Swap 事件和交易发起者信息，识别符合典型三明治攻击模式的交易组合，并提供可复现的检测结果。

需要解决的核心问题包括：

- 如何从区块内交易中筛选潜在攻击组合？
- 如何判断攻击者前后交易是否具有一致性？
- 如何区分攻击交易与正常交易、边界交易？
- 如何对检测结果进行结构化表达？
- 如何通过标注数据集评估检测算法的准确性？

## 1.3 项目目标

当前阶段构建一个独立运行的 Python 检测内核，实现：

- 基于本地 JSON Fixture 加载标准化交易数据。
- 识别同一流动性池内的典型三明治交易三联体。
- 输出结构化攻击匹配结果及命中原因。
- 计算 Quote Token 毛收益信号。
- 基于 Ground Truth 完成 Precision、Recall 和 F1 评估。

## 1.4 项目价值

本项目定位于事后检测与分析，而不是实时攻击阻断。

其价值在于：

- 自动识别已发生的典型三明治攻击。
- 为链上交易安全审计提供结构化分析结果。
- 为受害者交易复盘提供候选证据。
- 为后续攻击模式研究和防御策略优化提供数据基础。

当前 MVP 不承担资金追回、交易拦截或完整链上取证职责。
